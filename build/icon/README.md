# アプリアイコンの素材 — 要件

**ここに置いた PNG が、そのままの画素で `build/icon.ico`（Windows）と `build/icon.icns`（macOS）に入ります。**

---

## 1. ファイル構成

### 必須（9 枚）

| ファイル | 主な出番 |
|---------|---------|
| `16.png` | エクスプローラの「詳細」「一覧」表示、ジャンプリスト |
| `20.png` | 16 の 125% DPI 版 |
| `24.png` | タスクバー（100% DPI） |
| `32.png` | デスクトップショートカット（100% DPI）、Alt+Tab |
| `40.png` | 32 の 125% DPI 版 |
| `48.png` | エクスプローラ「中アイコン」（既定の表示） |
| `64.png` | 48 の 133% DPI 版 |
| `128.png` | 256 と 64 の中間。スケーリングの品質を稼ぐ |
| `256.png` | 「特大アイコン」。各所のスケーリング元 |

**9 枚すべてが必須です。** 1 枚でも欠けるとビルドが止まり、どれが足りないかが表示されます。

サイズを増減したいときは `scripts/make-icon.mjs` の `SIZES` とこの表の両方を直してください。
なお `.ico` は **1 辺 256px が上限**です（ICO 形式がサイズを 1 バイトで持つため。512 は格納できません）。

### 任意（macOS 用の高解像度）

| ファイル | 主な出番 |
|---------|---------|
| `512.png` | Finder の大きなアイコン表示、クイックルック |
| `1024.png` | 上の Retina 版 |

**無くてもビルドは通ります。** 無い場合、その大きさで表示される場面だけ 256px からの拡大になります
（Dock は Retina でも最大 256px なので影響しません）。置けば次の `npm run icon` から `.icns` に入ります。
置いた場合は必須の 9 枚と同じ検査（下の R1〜R3）が掛かります。`.ico` には入りません。

### macOS の `.icns` に入るもの

macOS は「表示サイズ（pt）× 倍率」で枠を持つため、同じ素材が 2 つの枠に入ることがあります。
`20` / `24` / `40` / `48` の枠は `.icns` に無いので、これらは Windows 専用です。

| 素材 | 入る枠 |
|------|-------|
| `16.png` | 16pt |
| `32.png` | 16pt の 2x、32pt |
| `64.png` | 32pt の 2x |
| `128.png` | 128pt |
| `256.png` | 128pt の 2x、256pt |
| `512.png`（任意） | 256pt の 2x、512pt |
| `1024.png`（任意） | 512pt の 2x |

枠を増減したいときは `scripts/make-icon.mjs` の `ICNS_ENTRIES` とこの表の両方を直してください。

macOS のアイコンは角丸の四角い台座に余白を取る形が慣例です。Windows 向けの絵をそのまま使うと
Dock で他のアプリと大きさや形が揃わないことがあります。mac 用に描き分けたい場合は、
素材の置き場を OS ごとに分ける改修が必要です（現状は同じ素材を両方に使います）。

## 2. 必須要件（満たさないとビルドが止まる）

| # | 要件 | 検査内容 |
|---|------|---------|
| R1 | PNG 形式であること | 先頭 8 バイトの署名 |
| R2 | 正方形で、**ファイル名の数字と実寸が一致**すること（`32.png` は 32×32） | IHDR の幅・高さ |
| R3 | **8bit RGBA**（PNG の colorType 6 / bitDepth 8）であること | IHDR のカラータイプ・ビット深度 |

### R3 を必須にしている理由

**Windows 自体はパレット PNG も RGB PNG も 16bit PNG も読めます**（実測で確認済み）。
それでも弾いているのは、**読めてしまうせいで書き出しミスに気づけない**からです。

| 形式 | Windows | 実際どうなるか |
|------|:------:|---------------|
| パレット PNG（colorType 3） | 読める | `tRNS` が付かず**透過が消える**（背景が塗りつぶされた四角になる） |
| RGB PNG（colorType 2） | 読める | アルファチャンネルが無いので**四角になる** |
| 16bit RGBA（bitDepth 16） | 読める | 読み込み時に 8bit へ丸められる。**容量が倍になるだけで画質の得なし** |

いずれも Windows はエラーを出しません。配布してから気づくことになるため、入口で止めています。

## 3. 推奨要件（検査は通るが守ること）

| # | 要件 | 理由 |
|---|------|------|
| S1 | **インターレースをオフ**にする | Adam7 でも正常に表示されます（実測）が、アイコンに段階表示の出番は無く、ファイルが太るだけです |
| S2 | **メタデータを含めない** | PNG のバイト列をそのまま `.ico` に埋め込むため、ICC プロファイルや XMP がそのまま exe のサイズになります |
| S3 | 色空間は **sRGB** で統一する | 無くても読めますが、環境によって明るさが変わることがあります |
| S4 | 背景は透過 | — |
| S5 | 小さいサイズほど**細部を削る** | 等倍で輪郭が読めるかが基準。16px は「羽根に見えるシルエット」まで削ってよい。線を 1px に揃えてピクセルグリッドに乗せると滲みません |
| S6 | 四辺に少し余白を取る | Windows 11 で他アプリのアイコンと並んだときに大きさが揃います |

### 書き出し設定のまとめ

```
8bit RGBA / 非インターレース / sRGB / メタデータなし / 背景透過
```

- **Photoshop**: 「PNG-24」＋「透明部分」にチェック、「インターレース」のチェックを外す
- **GIMP**: エクスポート時に 8bpc RGBA、「インターレース (Adam7)」のチェックを外し、
  不要なチャンク（コメント・サムネイル）のチェックも外す
- **ImageMagick**: `-define png:color-type=6 -interlace none -strip`

## 4. 検査で防げないこと（重要）

**壊れた PNG・途中で切れた PNG は検査を通過します。**

検査は PNG の先頭 26 バイト（IHDR）しか見ていません。ファイルが途中で欠けていても、
署名・実寸・カラータイプは正しく読めてしまうため通過します。
そして **Windows もエラーを出さずに読み込み、結果は全画素が透明 ―― アイコンが消えます。**

つまりこの経路では、コピー失敗・書き出しの中断・同期ツールの競合などでファイルが欠けると、
**ビルドは成功し、exe も生成され、配布して初めて気づく**ことになります。

対策は運用で行ってください。

- 差し替えたら `npm run icon` のあと、**画像ビューアで 9 枚が実際に開けることを確認する**
- ファイルサイズが不自然に小さくないか見る
  （現在の仮画像では `16.png` が約 0.6KB、`256.png` が約 82KB。絵柄で変わるので絶対値ではなく
  「前回からの急な減り方」を見る）
- `npm run dist:dir` のあと、エクスプローラで `release/win-unpacked/FeatherTree.exe` の
  アイコンが「特大アイコン」表示と「詳細」表示の両方で出ているか確認する
- macOS では `release/mac-universal/FeatherTree.app` のアイコンを Finder のアイコン表示と
  リスト表示、起動後の Dock で確認する

---

## 5. 差し替え手順

1. このフォルダの PNG を置き換える（1 枚ずつでもよい）
2. `npm run icon` で `build/icon.ico` と `build/icon.icns` を作り直す（どちらの OS で実行しても両方できる）
   - 素材の検査だけなら `npm run icon -- --check`
3. 上の「4. 検査で防げないこと」の目視確認を行う
4. `npm run dist` で配布物を作る
   （`dist` は前段で `npm run icon` を自動実行するので、手順 2 は省けます）

## 7. 制限の出どころ

どれが動かせない制約で、どれがこちらの都合かの区別。

| 制限 | 出どころ | 変えられるか |
|------|---------|------------|
| `.ico` は 1 辺 256px が上限 | ICO 形式（サイズを 1 バイトで持つ） | 不可 |
| `.icns` に 20 / 24 / 40 / 48 が入らない | ICNS 形式（その大きさの枠が無い） | 不可 |
| 正方形 | ICO / Windows シェル | 実質不可 |
| PNG 圧縮での格納 | Windows Vista 以降が対応 | 対象は Win10/11（決定 8）なので問題なし |
| PNG のみ（BMP 格納は非対応） | `scripts/make-icon.mjs` の実装方針 | 実装を足せば可能 |
| 8bit RGBA 限定（R3） | `scripts/make-icon.mjs`（透過事故の防止） | 条件 1 行で緩和可 |
| 9 サイズすべて必須 | `scripts/make-icon.mjs`（抜けの検知） | `SIZES` で調整可 |
| ファイル名＝実寸（R2） | `scripts/make-icon.mjs`（取り違えの検知） | 可 |

## 8. 関連するファイル

- `scripts/make-icon.mjs` — ここの PNG を `build/icon.ico` と `build/icon.icns` に詰める（画像は作らない）
- `electron-builder.yml` — `win.icon: build/icon.ico` と `mac.icon: build/icon.icns` を指す
- `scripts/dist.mjs` — ビルド前に、その OS 用のアイコンがあるかを確かめる
- `build/icon.ico` / `build/icon.icns` — 生成物。版管理しない（`.gitignore` 済み）
- `build/icon-app.png` — 元絵のマスター。配布には使われない。
  開発時のウィンドウアイコン（macOS では Dock アイコン）は `build/icon/256.png` を読む（`packages/main/src/index.ts`）
